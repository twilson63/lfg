Definition and research

LFG is a procedural skill, not an agent runtime. Fast path means a shorter evidence-backed workflow for a clear, localized, reversible, low-risk change. It does not mean fewer checks for a security-sensitive change, or a permission bypass. Baseline: remote main and docs/risk-based-fast-path both at 2660db7, skill v2.4.0, two validators passing, 59 tests passing with three unregistered e2e marker warnings.

The supplied v1 draft is input, not a replacement for v2.4 safeguards. Preserve standing-artifact bootstrap, all trust-boundary exclusions, uncertainty handling, full-suite validation, bounded replanning, optional Jev gates and commit authorization. Use the existing SKILL.md as the workflow architecture/feature map and README.md plus CI as developer setup. Deployment/SRE changes are out of scope; no service is deployed.

Goals, constraints and non-goals

  • Replace line/file thresholds and blanket UI/copy exclusions with all-of risk and scope eligibility, explicit procedure, escalation and seven-category evaluation rubric.
  • Align optional Jev triage and PR slicing so neither silently reinstates file-count or specified-copy exclusions.
  • Keep one canonical skill. Increment to v2.5.0 and update README. Keep the published Jev API example unchanged.
  • Use synthetic public evaluation cases only. Never send private user prompts, credentials, raw shell output or browser data to external models.
  • No guarantee of model behavior, whole-task quality or elapsed-time savings from static checks or semantic routing checks. Do not claim GitHub CI passed without a recorded run.
  • Do not change the user's old main checkout, install the skill globally, deploy anything, merge main, or force-push unrelated work.
